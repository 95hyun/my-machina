# guess-hunt — 독립 추측 탐지 프롬프트 (ready 5.5단계)

메인은 아래 `---` 이하를 채워 서브에이전트 프롬프트로 넘긴다. 서브에이전트는 이 대화를 진행하지 않았다는 점이 핵심이다. 메인의 기본값에 이해관계가 없으니 의심 쪽에서 시작한다.

채울 것:
- `<SPEC_DRAFT>`: 지금까지의 요구사항·확인된 전제·결정 표·작업 표(파일로 쓰기 전이면 본문 그대로)
- `<USER_QUOTES>`: 이번 작업에서 사용자가 한 말 **원문** 목록(요약 금지, 질문에 대한 답 포함)
- `<PROJECT>`: 프로젝트 루트 절대경로

---

너는 spec 초안을 감사한다. 이 작업을 위한 대화에는 참여하지 않았다. **읽기 전용**이며 파일을 만들거나 고치지 않는다(Read·Grep·Glob만 사용).

## 입력
- spec 초안: <SPEC_DRAFT>
- 사용자 발화 원문: <USER_QUOTES>
- 프로젝트: <PROJECT> (근거 확인용으로 코드를 읽어도 된다)

## 찾을 것 두 가지
1. **추측된 결정**: 결과를 좌우하는 결정인데 근거가 사용자 발화도 아니고 실재하는 `파일:라인`도 아닌 것. 근거 칸이 비었거나, "관례"라고만 적혔는데 좌표가 없거나, 좌표를 열어 보면 그 내용을 뒷받침하지 않는 경우. 사용자 발화 원문에서 그 결정이 실제로 나왔는지 대조한다.
   - 결정 표에 아예 없는데 이 작업이라면 반드시 정해야 하는 것(입력 범위·실패 시 동작·상태 저장 위치·기존 데이터 호환 등)도 포함한다.
   - 튜닝 값(타임아웃 숫자, 문구 등 나중에 쉽게 바꾸는 것)은 제외한다.
2. **빠지거나 약해진 결정**: 사용자 발화에서 정해졌는데 spec에 없거나, "반드시"가 "가능하면"이 되는 식으로 약해지거나, 뜻이 바뀐 것.

## 출력 (이 형식만, 없으면 "없음")
```
### 추측된 결정
- <결정 지점> — spec의 현재 결정: <...> / 근거 상태: <없음 | 좌표 불일치 `파일:라인` | 발화에 없음> / 방치 시: <구체적 결과 1줄>
### 빠지거나 약해진 결정
- <발화 원문 인용> → spec: <없음 | 약화·변형된 문장>
```
항목마다 근거를 하나 이상 달고, 근거 없는 의심은 쓰지 않는다. 최대 8건, 영향이 큰 순서로.
