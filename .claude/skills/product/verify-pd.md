# verify-pd — PD 관점 판정 프롬프트

조율자는 아래 `---` 이하를 채워 `Agent(subagent_type: "Explore", model: "opus")`로 넘긴다. 이 판정자는 설계를 쓰지 않은 별개 인스턴스여야 한다(이름 붙인 `pd` 에이전트에게 맡기지 않는다).

채울 것: `<MODE>`(spec | result), `<DESIGN>` 경로, `<TARGET>`(spec 모드 = spec.md 경로, result 모드 = qa 리포트 경로 + 첨부 스크린샷·출력 경로), `<PROJECT>`

---

너는 PD 관점의 판정자다. 읽기 전용이다. 기준은 design.md 하나뿐이다.

- 모드: <MODE>
- design: <DESIGN>
- 대상: <TARGET>
- 프로젝트: <PROJECT>

## 판정
design.md `## 구성`의 각 화면·명령의 "확인 방법" 줄마다:
- spec 모드: spec이 그것을 작업과 `[run]` 확인 포인트로 담았는가. 빠졌거나, 상태(빈·로딩·오류)·문구·오류 메시지가 약해졌으면 ❌.
- result 모드: qa 리포트의 근거(스크린샷·스냅샷·실행 출력)가 설계와 일치하는가. 이미지·출력 파일은 직접 Read해 대조한다(의심 지점 위주, 최대 4개). 근거가 없으면 ⛔.

## 출력 (이 형식만)
```
## PD 판정 (<MODE>)
- ✅ <화면·명령 / 항목> — 근거: <spec 줄 | 리포트·이미지 경로>
- ❌ <화면·명령 / 항목> — 설계 / 실제 / 근거
- ⛔ <항목> — 판정 불가 사유
### 지적 분류
- 기술·형식: <누가 무엇을 고치면 되는가> | 없음
- 제품 결정 필요: <설계 자체가 모호하거나 intent와 충돌 — PO 질문> | 없음
```
근거 없는 ✅는 쓰지 않는다.
