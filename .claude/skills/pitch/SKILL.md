# /pitch — 데모·피치·Q&A 준비

먼저 `hackathon/RULES.md`를 Read한다(해커톤 공통 규칙 — 이 세션에서 이미 읽었으면 생략).

에이전트 스폰 없음. 새 웹검색 없음(원페이저의 출처를 재사용).

## 0. 준비
- `hackathon/runs/CURRENT`를 Read → `$RUN`. `$RUN/05-pitch.md`가 이미 있으면 2단계 보고로 바로. `$RUN/03-final.md`, 확정 원페이저, `$RUN/03-redteam.md`(해당 후보), `$RUN/04-mvp.md`의 데모 스크립트, `$RUN/01-topics.md`의 확정 주제·VC가 볼 것만 Read.
- 인자가 `grill`이면 바로 3단계로.
- `./hackathon/bin/mark pitch start`.

## 1. `$RUN/05-pitch.md` 작성
### 피치 스토리 (발표 시간 기준, 기본 3~5분)
1. 훅 — 페르소나 한 명의 장면(숫자 1개)
2. 문제 — 문제 정의 문장, 기존 방법의 한계
3. 데모 — `04-mvp.md` 스크립트로 넘김
4. 왜 우리·왜 지금
5. 사업성 — 누가 얼마 내나, 바텀업 시장, 첫 100명 GTM
6. 마무리 — VC 주제 문장에 정면으로 답하는 한 줄

### 덱 아웃라인 (6~8장)
| # | 제목(주장형 문장) | 화면에 둘 것 | 말할 것 |
|---|---|---|---|

### 사업성 숫자
- 가격(USD)·과금 단위, 단위 경제성(건당/유저당 수익 − 원가(LLM 호출비 포함)), 바텀업 시장 계산식.
- 원페이저의 출처는 그대로 링크, `가정`은 `가정`으로 남긴다. 숫자를 새로 지어내지 않는다.

### 예상 심사 질문 10개
레드팀 질문을 포함해 아픈 순서로. 각 질문에 **답 2줄 + 근거(원페이저 섹션)**. 답이 약한 질문은 ⚠️ 표시.

## 2. 보고
덱 아웃라인과 ⚠️ 질문만 화면에 보여주고, "모의 질의 하려면 `/pitch grill`" 안내. `./hackathon/bin/mark pitch end`.

## 3. grill — 모의 질의
당신은 이 주제를 낸 VC 심사위원이다. 05-pitch.md의 질문 + 새 질문으로 **한 번에 하나씩** 묻고, 사람이 답하면 2줄 피드백(무엇이 약했나, 더 나은 한 문장) 후 다음 질문. 5개 또는 사람이 "그만"이면 종료하고, 약했던 답을 05-pitch.md의 해당 질문 아래 `개선 답`으로 갱신한다.
