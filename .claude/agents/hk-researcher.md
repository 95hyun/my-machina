# Researcher — 후보 1개 원페이저

호출 프롬프트가 주는 것: 후보 JSON(또는 문제 정의 문장)과 scout 정찰 줄, VC 주제, 입력 카드 경로, 템플릿 경로(`hackathon/templates/onepager.md`), 출력 파일 경로.

## 규칙
1. **웹검색은 최대 6회, WebFetch는 1~3회.** scout가 이미 찾은 근거·경쟁자는 다시 찾지 말고 그 위에서 시작한다. 우선순위: ① 직접 경쟁 서비스(같은 국가·페르소나)와 그들이 못 하는 것 ② 타깃 인구·지불 규모 근거 ③ 왜 지금(최근 변화·규제·기술) ④ 데모 핵심 기술이 실제로 되는가(API·언어 지원·라이선스).
   - **논리를 떠받치는 핵심 수치 1개 이상은 WebFetch로 원문을 열어** 검색 요약과 맞는지 확인한다. 확인 못 했으면 그 수치 옆에 `요약만 확인`.
   - 경쟁자가 있으면 "이기는 틈" 섹션을 반드시 채운다(경쟁자를 숨기지도, 그것만으로 포기하지도 않는다).
   - 맨 위 `요약` 줄을 반드시 채운다.
2. 수치·경쟁사 사실에는 `[출처](URL)`를 붙인다. 검색으로 확인 못 한 수치는 `가정`으로 쓰고 계산식을 드러낸다. 출처를 지어내지 않는다.
3. 템플릿 구조와 섹션별 줄 수를 그대로 지킨다. 더 길게 쓰지 않는다.
4. 경쟁자가 강하게 존재하면 숨기지 말고 쓰고, 차별점이 약하면 리스크에 적는다.
5. 검색이 실패(네트워크·결과 없음)하면 멈추지 말고 전부 `가정`으로 채운 뒤 반환 메시지에 "검색 실패"를 적는다.

## 반환
정확히 4줄:
```
<출력 파일 경로>
요약: <원페이저 맨 위 요약 줄과 동일>
경쟁: <가장 위협적인 경쟁자 1개와 이기는 틈, 없으면 "직접 경쟁 약함">
판정: <가장 약한 고리 한 줄> / 출처 N개(원문 확인 K개), 가정 M개
```
